# Детальна теорія до уроку 7. Умови й логіка

> Тут пояснено, як програма «приймає рішення»: логічні вирази, оператори порівняння та логічні оператори з таблицями істинності, конструкції `if` / `else if` / `else`, змінні-перемикачі, перевірка «миша над фігурою» і фізика м'яча, що відскакує.

## 1. Програма, що вибирає

Досі програма виконувала **всі** рядки підряд. Умова дозволяє виконати частину коду **лише якщо** щось правда. Так ми міркуємо щодня: «**якщо** йде дощ, **то** беру парасолю, **інакше** — кепку».

## 2. Логічні вирази

**Логічний (булевий) вираз** — це питання, на яке комп'ютер відповідає `true` (правда) або `false` (неправда). Назва походить від прізвища математика Джорджа Буля.

### Оператори порівняння

| Оператор | Значення | Приклад | Результат, якщо x = 5 |
|---|---|---|---|
| `>` | більше | `x > 3` | true |
| `<` | менше | `x < 3` | false |
| `>=` | більше або дорівнює | `x >= 5` | true |
| `<=` | менше або дорівнює | `x <= 4` | false |
| `==` | **дорівнює** | `x == 5` | true |
| `!=` | **не** дорівнює | `x != 5` | false |

⚠️ Найпоширеніша помилка: `=` — присвоїти, `==` — порівняти. `if (x = 5)` у Processing — помилка.

⚠️ Текст (`String`) порівнюють не через `==`, а методом `.equals()`: `if (name.equals("Оля"))`.

## 3. Конструкції `if`

### Лише `if`

```java
if (умова) {
  // виконується, тільки якщо умова true
}
```

### `if` + `else`

```java
if (умова) {
  // якщо true
} else {
  // якщо false
}
```

Виконується **рівно одна** з двох гілок.

### Ланцюжок `if` / `else if` / `else`

```java
if (score >= 10) {
  println("високий рівень");
} else if (score >= 7) {
  println("достатній рівень");
} else if (score >= 4) {
  println("середній рівень");
} else {
  println("початковий рівень");
}
```

Умови перевіряються **зверху вниз**. Виконується гілка **першої** правдивої умови, решта пропускається. Тому порядок важливий: якби першою стояла перевірка `score >= 4`, оцінка 11 потрапила б у «середній рівень».

### Покрокова перевірка для score = 8

| Перевірка | Результат | Що далі |
|---|---|---|
| `8 >= 10` | false | до наступної |
| `8 >= 7` | **true** | виводимо «достатній рівень», **решту пропускаємо** |

### Фігурні дужки

Якщо в гілці **одна** команда, дужки можна не писати: `if (x > width) x = 0;`. Але коли команд кілька, без дужок умова стосуватиметься лише першої з них. Тому новачкам радимо писати `{ }` завжди.

## 4. Логічні оператори

Щоб поєднати кілька умов:

| Оператор | Значення | Читаємо як |
|---|---|---|
| `&&` | І (AND) | «і те, і інше» |
| `\|\|` | АБО (OR) | «хоча б одне» |
| `!` | НЕ (NOT) | «навпаки» |

### Таблиці істинності

| A | B | A && B | A \|\| B |
|---|---|---|---|
| true | true | **true** | true |
| true | false | false | true |
| false | true | false | true |
| false | false | false | **false** |

| A | !A |
|---|---|
| true | false |
| false | true |

Запам'ятати легко:
- `&&` правдиве, лише коли **обидві** частини правдиві;
- `||` хибне, лише коли **обидві** частини хибні.

### Приклади

```java
x > 10 && x < 50          // x між 10 і 50
key == 'q' || key == 'Q'  // натиснуто q у будь-якому регістрі
!gameOver                 // гра НЕ закінчена
```

⚠️ Не можна писати як у математиці `10 < x < 50`. Треба розбити на дві умови: `x > 10 && x < 50`.

## 5. Чи миша над фігурою (rollover)

### Над прямокутником

Курсор усередині прямокутника `rect(x, y, w, h)`, якщо він **одночасно**:
- правіше лівого краю: `mouseX > x`
- лівіше правого краю: `mouseX < x + w`
- нижче верхнього краю: `mouseY > y`
- вище нижнього краю: `mouseY < y + h`

```java
int x = 100, y = 80, w = 200, h = 100;

void setup() {
  size(400, 260);
}

void draw() {
  background(255);
  if (mouseX > x && mouseX < x + w && mouseY > y && mouseY < y + h) {
    fill(255, 160, 0);     // курсор над прямокутником
  } else {
    fill(200);
  }
  rect(x, y, w, h);
}
```

### Над колом

Курсор усередині кола, якщо **відстань** від курсора до центру менша за **радіус**:

```java
if (dist(mouseX, mouseY, cx, cy) < d / 2) { ... }
```

`d / 2` — бо в `ellipse()` ми задаємо діаметр, а порівнювати треба з радіусом.

## 6. Змінна-перемикач (`boolean`)

Логічна змінна запам'ятовує **стан**: увімкнено / вимкнено, гра йде / пауза.

```java
boolean isOn = false;

void setup() {
  size(300, 200);
}

void draw() {
  if (isOn) {              // те саме, що if (isOn == true)
    background(255, 230, 120);
  } else {
    background(40);
  }
}

void mousePressed() {
  isOn = !isOn;            // перемкнути: true → false, false → true
}
```

`isOn = !isOn` читаємо так: «новий стан — протилежний до старого».

## 7. М'яч, що відскакує: швидкість як змінна

Щоб м'яч міг повернути, **швидкість** має бути окремою змінною, яка може бути додатною або від'ємною:

| Значення `xSpeed` | Напрямок руху |
|---|---|
| додатне (3) | праворуч |
| від'ємне (−3) | ліворуч |
| 0 | стоїть |

Відскок — це **зміна знака** швидкості: `xSpeed = xSpeed * -1;` (або `xSpeed *= -1;`).

```java
float x = 50, y = 80;
float xSpeed = 3, ySpeed = 2;
float r = 15;              // радіус м'яча

void setup() {
  size(400, 300);
}

void draw() {
  background(255);
  x += xSpeed;
  y += ySpeed;
  if (x > width - r || x < r) xSpeed *= -1;    // правий або лівий край
  if (y > height - r || y < r) ySpeed *= -1;   // нижній або верхній край
  ellipse(x, y, r * 2, r * 2);
}
```

Чому `width - r`, а не `width`? Бо `x` — це **центр** м'яча. Щоб м'яч відскакував, коли **край** торкається стінки, від межі треба відняти радіус. Інакше м'яч наполовину «залазить» у стінку.

## 8. Трохи фізики: гравітація

| Величина | Що означає | Як змінюється щокадру |
|---|---|---|
| положення `y` | де м'яч | `y += ySpeed;` |
| швидкість `ySpeed` | на скільки зміщується за кадр | `ySpeed += gravity;` |
| прискорення `gravity` | на скільки зростає швидкість за кадр | стале, наприклад 0.2 |

Гравітація **збільшує швидкість падіння** щокадру, тому м'яч падає дедалі швидше. Під час відскоку від підлоги швидкість змінює знак і трохи зменшується (`ySpeed *= -0.9`): м'яч втрачає енергію і кожен наступний стрибок нижчий.

⚠️ Важлива деталь: після відскоку поверніть м'яч на межу (`y = height - r;`). Інакше він може «застрягти» за підлогою: швидкість змінює знак щокадру, і м'яч тремтить.

## 9. Корисні функції замість умов

| Функція | Замінює |
|---|---|
| `constrain(x, 0, width)` | `if (x < 0) x = 0; if (x > width) x = width;` |
| `min(a, b)` / `max(a, b)` | `if (a < b) ... else ...` для вибору меншого/більшого |
| `abs(x)` | `if (x < 0) x = -x;` |

## 10. Типові помилки

| Що сталося | Причина |
|---|---|
| `if (x = 5)` — помилка | для порівняння потрібно `==` |
| `if (x > 5);` — умова «не працює» | крапка з комою після `if (...)` закінчує команду, і блок `{ }` виконується завжди |
| спрацьовує не та гілка | неправильний порядок у ланцюжку `else if` |
| м'яч застрягає в стінці | межу перевірено без радіуса або м'яч не повернуто на межу |
| `10 < x < 50` — помилка | треба `x > 10 && x < 50` |

## 11. Шпаргалка

```java
if (a > b) { ... } else if (a == b) { ... } else { ... }
&&  і        ||  або        !  не
mouseX > x && mouseX < x + w && mouseY > y && mouseY < y + h   // над прямокутником
dist(mouseX, mouseY, cx, cy) < r                                // над колом
flag = !flag;                                                   // перемикач
speed *= -1;                                                    // відскок
```

## 12. Перевір себе

1. Чому дорівнює `(5 > 3) && (2 > 4)`? А `(5 > 3) || (2 > 4)`?
2. Запишіть умову: «y від 100 до 200 включно».
3. Що виведе програма при `t = 25`: `if (t > 30) println("спека"); else if (t > 20) println("тепло"); else println("прохолодно");`?
4. Чому для відскоку множать на −1, а не просто пишуть `xSpeed = -3`?
5. Як перевірити, що курсор **поза** колом?

<details>
<summary>Відповіді</summary>

1. `false` (друга частина хибна); `true` (перша правдива).
2. `y >= 100 && y <= 200`
3. «тепло».
4. Множення на −1 змінює напрямок на протилежний, хоч би яким він був. `xSpeed = -3` завжди посилає м'яч ліворуч, навіть якщо він уже рухається ліворуч.
5. `dist(mouseX, mouseY, cx, cy) > r` або `!(dist(mouseX, mouseY, cx, cy) < r)`.
