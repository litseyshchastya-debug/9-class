# Детальна теорія до уроку 11. Класи й об'єкти

> Тут пояснено ідею об'єктно-орієнтованого програмування (ООП): з чого складається клас (поля, конструктор, методи), як створити об'єкт через `new`, як працює запис через крапку, що таке `this` і чому об'єкти одного класу незалежні.

## 1. Проблема, яку розв'язує ООП

Уявіть гру з трьома м'ячами. Кожен м'яч має координати x і y, швидкість, розмір і колір. Без ООП потрібно:

```java
float x1, y1, speedX1, speedY1, d1;
float x2, y2, speedX2, speedY2, d2;
float x3, y3, speedX3, speedY3, d3;
```

і так само по три копії кожної дії. Для 100 м'ячів це неможливо підтримувати.

**Об'єктно-орієнтоване програмування** пропонує інше: описати **один раз**, що таке «м'яч взагалі» (які дані він має і що вміє), а потім створити скільки завгодно **конкретних** м'ячів.

## 2. Клас і об'єкт

| Поняття | Аналогія | У програмі |
|---|---|---|
| **клас** | формочка для печива; креслення будинку | опис: які дані й дії має кожен м'яч |
| **об'єкт** (екземпляр) | печиво, вирізане формочкою; збудований будинок | конкретний м'яч з власними координатами |

Одна формочка — скільки завгодно печива. Кожне печиво можна по-своєму прикрасити (у кожного об'єкта **власні значення** полів), але форма в усіх однакова.

## 3. Анатомія класу

```java
class Ball {
  // ── 1. ПОЛЯ: дані, які має кожен м'яч ──
  float x, y;
  float speedX, speedY;
  float d;
  color c;

  // ── 2. КОНСТРУКТОР: як «зібрати» новий м'яч ──
  Ball(float startX, float startY, float diameter) {
    x = startX;
    y = startY;
    d = diameter;
    speedX = random(-3, 3);
    speedY = random(-3, 3);
    c = color(random(255), random(255), random(255));
  }

  // ── 3. МЕТОДИ: що вміє м'яч ──
  void move() {
    x += speedX;
    y += speedY;
  }

  void bounce() {
    if (x < d/2 || x > width - d/2) speedX *= -1;
    if (y < d/2 || y > height - d/2) speedY *= -1;
  }

  void display() {
    fill(c);
    ellipse(x, y, d, d);
  }
}
```

### Поля

**Поля** (fields) — це змінні, оголошені всередині класу, але поза його методами. Кожен об'єкт має **власний комплект** полів. У м'яча №1 своє `x`, у м'яча №2 — своє.

### Конструктор

**Конструктор** — особлива функція, яка виконується **один раз**, коли об'єкт створюють. Вона задає початкові значення полів.

Як упізнати конструктор:
- його назва **точно збігається** з назвою класу (`Ball`);
- перед ним **немає типу**, навіть `void`;
- його параметри — «налаштування», які передають при створенні.

Чому параметри конструктора мають інші назви (`startX`, а не `x`)? Якби назвати параметр `x`, рядок `x = x;` присвоїв би параметр самому собі, а поле залишилося б нулем. Шиффман радить додавати до параметрів префікс `temp` (`tempX`) або давати інші назви.

### Методи

**Методи** — це функції, що належать класу. Вони описують **поведінку** об'єкта і працюють з **його** полями. Усередині методу `move()` слово `x` означає «x **цього** м'яча».

## 4. Використання класу: три кроки

```java
Ball b1;                      // 1. ОГОЛОСИТИ змінну типу Ball (поки «порожня»)
Ball b2;

void setup() {
  size(400, 300);
  b1 = new Ball(100, 100, 40);  // 2. СТВОРИТИ об'єкт: new + конструктор
  b2 = new Ball(250, 150, 70);
}

void draw() {
  background(255);
  b1.move();                  // 3. КЕРУВАТИ: об'єкт.метод()
  b1.bounce();
  b1.display();
  b2.move();
  b2.bounce();
  b2.display();
}
```

*(Щоб приклад запустився, клас `Ball` з розділу 3 має бути в тому самому скетчі, наприклад у другій вкладці.)*

### Ключове слово `new`

`new Ball(100, 100, 40)` означає: «виділити пам'ять для нового м'яча і виконати його конструктор з аргументами 100, 100, 40». Без `new` змінна `b1` залишається **порожньою** (`null`), і виклик `b1.move()` спричинить помилку **NullPointerException** — «звернення до неіснуючого об'єкта».

### Крапка — «доступ до вмісту об'єкта»

| Запис | Значення |
|---|---|
| `b1.move()` | викликати метод `move` **об'єкта** `b1` |
| `b1.x` | прочитати поле `x` об'єкта `b1` |
| `b1.speedX = 0;` | змінити поле об'єкта `b1` |

Крапку можна читати як українське «у»: `b1.x` — «x у b1».

## 5. Об'єкти незалежні

Виклик `b1.move()` змінює **лише** поля `b1`. М'яч `b2` про це «не знає». Тому код усіх м'ячів однаковий, а поводяться вони по-різному: у кожного свої координати, швидкість і колір.

## 6. Ключове слово `this`

Усередині класу `this` означає «**цей** об'єкт». З ним параметри конструктора можна назвати так само, як поля:

```java
Ball(float x, float y, float d) {
  this.x = x;    // поле x цього м'яча = параметр x
  this.y = y;
  this.d = d;
}
```

## 7. Методи з параметрами і з результатом

Методи — звичайні функції, тож вони можуть мати параметри й повертати значення:

```java
boolean isUnderMouse() {                 // повертає true/false
  return dist(mouseX, mouseY, x, y) < d / 2;
}

void setColor(color newColor) {          // приймає параметр
  c = newColor;
}

boolean intersects(Ball other) {         // параметр — інший об'єкт!
  return dist(x, y, other.x, other.y) < d/2 + other.d/2;
}
```

Використання: `if (b1.isUnderMouse()) b1.setColor(color(255, 0, 0));` або `if (b1.intersects(b2)) { ... }`.

## 8. Класи у вкладках

Клас можна написати в тому самому файлі, але зручніше винести його в **окрему вкладку**: стрілка біля вкладок → *New Tab*, назва — як у класу (`Ball`). Processing під час запуску об'єднує всі вкладки в одну програму. В онлайн-середовищі вкладку додає кнопка «+».

## 9. Словник ООП

| Термін | Англійською | Пояснення |
|---|---|---|
| клас | class | шаблон, опис |
| об'єкт, екземпляр | object, instance | конкретна «річ», створена за класом |
| поле | field | змінна всередині класу |
| метод | method | функція всередині класу |
| конструктор | constructor | метод, що виконується під час створення (`new`) |
| інкапсуляція | encapsulation | дані й дії над ними «упаковані» разом |

## 10. Типові помилки

| Повідомлення / поведінка | Причина |
|---|---|
| `NullPointerException` | об'єкт оголошено, але не створено через `new` |
| `The constructor Ball(int, int) is undefined` | аргументів у `new Ball(...)` не стільки, скільки параметрів у конструкторі |
| усі поля об'єкта дорівнюють 0 | у конструкторі написано `x = x;` (параметр має ту саму назву, що й поле) |
| `void Ball(...)` — об'єкт не налаштовується | перед конструктором стоїть тип: тоді це звичайний метод, а не конструктор |
| `Cannot find a class or type named "ball"` | регістр: клас `Ball`, назви класів пишуть з **великої** літери |
| м'ячі не рухаються | методи `move()` не викликано в `draw()` |

## 11. Шпаргалка

```java
class Назва {
  тип поле;                         // дані
  Назва(тип параметр) {             // конструктор
    поле = параметр;
  }
  void метод() { ... }              // поведінка
}

Назва obj;                          // оголосити
obj = new Назва(аргумент);          // створити
obj.метод();   obj.поле;            // використати
```
