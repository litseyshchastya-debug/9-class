## 1. Декомпозиція: від ідеї до коду

**Декомпозиція** — розбиття великої задачі на маленькі, кожну з яких легко розв'язати окремо. Так будують будинок: фундамент, стіни, дах, а не «будинок одразу».

Як працювати над програмою (за Шиффманом):
1. **Опишіть ідею словами**: «краплі падають, гравець ловить їх миською, за пропущену краплю втрачає життя».
2. **Виділіть частини (іменники та дієслова)**. Іменники — майбутні **класи** (`Drop`, `Catcher`, `Timer`), дієслова — **методи** (`move`, `catch`, `display`).
3. **Зробіть кожну частину окремим маленьким скетчем** і перевірте, що вона працює.
4. **Об'єднайте** частини.
5. Лише після цього **додавайте** «прикраси»: рахунок, рівні, звук.

## 2. Псевдокод

**Псевдокод** — план програми звичайною мовою, але в структурі коду. Його пишуть **до** коду, щоб продумати логіку:

```
кожен кадр:
  намалювати фон
  якщо минула секунда → додати нову краплю
  для кожної краплі:
    зрушити вниз
    якщо торкається ловця → +1 бал, прибрати краплю
    інакше якщо впала нижче екрана → −1 життя, прибрати
  якщо життів 0 → екран «кінець гри»
```

Псевдокод можна залишити в програмі як **коментарі** і дописувати під ними код.

## 3. Час

### `millis()` — секундомір від запуску

| Функція | Повертає |
|---|---|
| `millis()` | скільки **мілісекунд** минуло від запуску програми (1 с = 1000 мс) |
| `second()` | секунди системного годинника, 0–59 |
| `minute()` | хвилини, 0–59 |
| `hour()` | години, 0–23 |
| `day()`, `month()`, `year()` | дата |

`frameCount` теж вимірює час, але в **кадрах**. Якщо комп'ютер гальмує, кадрів стає менше. `millis()` показує **справжній** час незалежно від швидкості комп'ютера.

### Таймер: «чи минув інтервал?»

Ідея: запам'ятати момент старту і порівнювати поточний час з ним.

```
скільки минуло = millis() − момент_старту
```

```java
int savedTime;
int interval = 2000;     // 2 секунди
int count = 0;

void setup() {
  size(300, 200);
  savedTime = millis();
}

void draw() {
  background(255);
  int passed = millis() - savedTime;
  if (passed > interval) {
    count++;                  // подія!
    savedTime = millis();     // перезапустити таймер
  }
  fill(0);
  textSize(20);
  text("Минуло: " + passed + " мс", 20, 80);
  text("Подій: " + count, 20, 120);
}
```

### Покрокова перевірка

| Кадр | millis() | savedTime | passed | `passed > 2000`? |
|---|---|---|---|---|
| 1 | 16 | 0 | 16 | ні |
| … | … | … | … | … |
| 121 | 2016 | 0 | 2016 | **так** → count = 1, savedTime = 2016 |
| 122 | 2033 | 2016 | 17 | ні |

Таймер можна оформити класом `Timer` з методами `start()` і `isFinished()`: так зроблено в грі «Ловець».

## 4. Стани програми (екрани гри)

У гри є кілька «екранів»: меню, гра, пауза, кінець. Усі вони живуть в одному `draw()`, але щокадру показується **один**. Який саме — зберігає змінна **стану**:

```java
int state = 0;   // 0 — меню, 1 — гра, 2 — кінець

void draw() {
  if (state == 0) {
    drawMenu();
  } else if (state == 1) {
    playGame();
  } else if (state == 2) {
    drawGameOver();
  }
}
```

### Переходи між станами

```
          клік                 життя = 0
 ┌──────┐ ─────► ┌──────┐ ──────────────► ┌──────────┐
 │ меню │        │ гра  │                 │  кінець  │
 └──────┘        └──────┘ ◄────────────── └──────────┘
                              клік (restart)
```

Переходи відбуваються в **одному місці**: зміною `state`. Наприклад, у `mousePressed()`: `if (state == 0) state = 1;`.

Порада: замість «чарівних» чисел 0, 1, 2 можна оголосити константи: `final int MENU = 0, PLAY = 1, OVER = 2;` і писати `if (state == PLAY)`. Слово `final` означає, що значення змінити не можна.

### Перезапуск

Функція `restart()` повертає **усі** змінні гри до початкових значень: рахунок 0, життя 3, порожній список крапель. Без неї друга гра почнеться з рахунком першої.

## 5. Зіткнення (collision detection)

| Що з чим | Умова зіткнення |
|---|---|
| точка і коло | `dist(px, py, cx, cy) < r` |
| два кола | `dist(x1, y1, x2, y2) < r1 + r2` |
| точка і прямокутник | `px > rx && px < rx + rw && py > ry && py < ry + rh` |
| два прямокутники | `x1 < x2 + w2 && x1 + w1 > x2 && y1 < y2 + h2 && y1 + h1 > y2` |

### Два кола

Кола торкаються, коли відстань між центрами дорівнює **сумі радіусів**. Менша відстань — кола перекриваються.

```
   ○ r1      ○ r2
   ●─────────●
   └── dist ──┘      dist < r1 + r2  →  зіткнення
```

### Два прямокутники

Прямокутники **не** перетинаються, якщо один повністю ліворуч, праворуч, вище або нижче за інший. Умова з таблиці — це заперечення цих чотирьох випадків.

```java
boolean rectsOverlap(float x1, float y1, float w1, float h1,
                     float x2, float y2, float w2, float h2) {
  return x1 < x2 + w2 && x1 + w1 > x2 && y1 < y2 + h2 && y1 + h1 > y2;
}
```

## 6. Налагодження (debugging)

**Баг** — помилка в програмі, **налагодження** — її пошук і виправлення.

### Три види помилок

| Вид | Коли проявляється | Приклад | Як шукати |
|---|---|---|---|
| **синтаксична** | Processing не запускає програму | пропущена `;`, незакрита `}` | червоне підкреслення і повідомлення в консолі з номером рядка |
| **помилка виконання** | програма запустилась і аварійно зупинилась | NullPointerException, вихід за межі масиву | текст помилки + підсвічений рядок |
| **логічна** | програма працює, але **не так**, як задумано | м'яч проходить крізь стіну, рахунок не росте | `println()`, налагоджувач, спрощення коду |

Найпідступніші — логічні помилки: комп'ютер не скаржиться, бо робить рівно те, що написано.

### П'ять порад Шиффмана

1. **Зробіть перерву.** Свіжий погляд за 5 хвилин знаходить те, чого не видно після години.
2. **Поясніть комусь** (хоч гумовій качечці) рядок за рядком, що робить код. Помилка часто знаходиться, поки ви пояснюєте.
3. **Спрощуйте.** Закоментуйте половину коду. Помилка зникла — вона в закоментованій частині; ні — в іншій. Діліть далі, поки не знайдете.
4. **Друкуйте значення.** `println("x = " + x + ", speed = " + speed);` показує, що програма «думає». Часто виявляється, що змінна має зовсім не те значення, якого ви чекали.
5. **Пишіть маленькими кроками.** Кілька рядків — запуск — перевірка. Якщо щойно додані 3 рядки зламали програму, помилка в цих 3 рядках.

### Налагоджувач (debugger) у Processing

1. Натисніть кнопку *Debug* (метелик) на панелі.
2. Клацніть на **номері рядка** — з'явиться точка зупинки (breakpoint).
3. Запустіть: програма **зупиниться** на цьому рядку.
4. Подивіться значення змінних у панелі *Variables*.
5. Кнопка *Step* виконує **один** рядок і знову зупиняється.

## 7. Як читати повідомлення про помилки

| Повідомлення | Означає | Що перевірити |
|---|---|---|
| `missing a semicolon` | пропущена `;` | кінець вказаного або попереднього рядка |
| `missing right curly bracket "}"` | не закрито `{` | порахуйте пари дужок, натисніть Ctrl+T |
| `The variable "xx" does not exist` | змінна не оголошена або не видна тут | назву, регістр, де оголошено |
| `The function "xx" does not exist` | немає такої функції з такими аргументами | назву, кількість і типи аргументів |
| `Type mismatch` | значення не того типу | `int` ← `float`? |
| `NullPointerException` | об'єкт не створено | чи є `new`? чи завантажено файл? |
| `ArrayIndexOutOfBoundsException: N` | індекс N поза масивом | межі циклу, `length - 1` |
