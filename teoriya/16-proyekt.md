# Детальна теорія до уроків 16–17. Як створити власний проєкт

> Тут пояснено, як пройти шлях від ідеї до готової програми: обрати і звузити задум, спланувати структуру, писати код маленькими кроками, оформити його так, щоб його легко було читати, перевірити, експортувати і презентувати.

## 1. Етапи проєкту

```
 ідея → ескіз на папері → план (класи, функції) → прототип → розвиток → тестування → презентація
```

Кожен етап має **результат**, який можна показати вчителю. Це допомагає не загубитися.

| Етап | Що зробити | Результат |
|---|---|---|
| Ідея | 3–5 речень: що бачить і робить користувач | опис |
| Ескіз | малюнок на папері в клітинку з координатами | ескіз |
| План | список класів, функцій, змінних | таблиця або псевдокод |
| Прототип | найпростіша робоча версія **головної** механіки | скетч, що запускається |
| Розвиток | додавання функцій по одній | версії 1, 2, 3… |
| Тестування | хтось інший пробує «зламати» програму | список виправлених помилок |
| Презентація | 3 хвилини: що, як, що складно, що далі | виступ |

## 2. Як обрати задум, який вдасться

**Головне правило — звузити.** «Зроблю Minecraft» — нереально. «Квадратик стрибає через перешкоди, які наближаються» — реально, і з цього може вирости цікава гра.

Перевірте задум питаннями:
- Чи можу я описати головну механіку **одним реченням**?
- Чи можна зробити найпростішу версію за **один урок**?
- Які теми курсу тут знадобляться?

### Від теми курсу до проєкту

| Тема | Як використати в проєкті |
|---|---|
| фігури, колір | стиль, персонажі, фон |
| змінні, анімація | рух, рахунок, таймери |
| миша, клавіатура | керування |
| умови | правила гри, кнопки, межі |
| цикли | сітки, візерунки, багато об'єктів |
| random, noise | різноманітність, природність |
| функції | порядок у коді, повторне використання |
| класи | гравець, вороги, частинки |
| масиви, ArrayList | багато об'єктів, що з'являються і зникають |
| sin, cos, трансформації | обертання, орбіти, хвилі |
| зображення, текст | меню, рахунок, спрайти |
| millis, стани | рівні, екрани, обмеження часу |

## 3. Планування структури

Шаблон опису проєкту (можна вставити в коментар на початку скетчу):

```
Назва: «Космічний ловець»
Ідея: зірки падають з неба, корабель внизу ловить їх; метеорити віднімають життя.
Керування: мишею по горизонталі.
Класи:  Ship (x, y, w; move(), display())
        Star (x, y, speed; fall(), display(), hitBy(ship))
        Meteor — як Star, але інший колір і наслідок
Глобальні змінні: score, lives, state, ArrayList<Star>, Timer
Стани: 0 — меню, 1 — гра, 2 — кінець
```

## 4. Мінімальний робочий прототип

**Прототип** — найпростіша версія, у якій **головна механіка вже працює**, хай і некрасиво: прямокутник замість корабля, кола замість зірок. Красу додаємо потім. Якщо щось не встигнете, у вас усе одно буде робоча програма.

Порядок розвитку «Космічного ловця»:
1. корабель рухається за мишею;
2. одна зірка падає;
3. зірку можна зловити (зіткнення) і рахунок росте;
4. багато зірок з `ArrayList` і таймером;
5. метеорити і життя;
6. екрани меню й кінця гри;
7. графіка, кольори, частинки, рекорд.

Після **кожного** пункту — запуск і перевірка.

## 5. Якість коду

Код читають люди: ви через тиждень, однокласник, учитель. Добрий код легко **читати** і **змінювати**.

| Правило | Погано | Добре |
|---|---|---|
| осмислені назви | `float a, b, c;` | `float shipX, shipSpeed, starSize;` |
| без «чарівних чисел» | `if (x > 573)` | `if (x > width - shipW)` |
| відступи | усе з початку рядка | вкладені блоки зсунуті (Ctrl+T) |
| коментарі пояснюють **навіщо** | `x++; // збільшити x` | `x++; // корабель зсувається праворуч щокадру` |
| одна функція — одна дія | 80 рядків у `draw()` | `draw()` викликає `move()`, `checkHits()`, `drawScore()` |
| класи в окремих вкладках | 300 рядків в одному файлі | `Ship`, `Star` — окремі вкладки |

### Шапка-коментар скетчу

```java
/*
  Космічний ловець
  Автор: Олена Коваль, 9-Б, 2026
  Керування: миша — корабель, клік — почати гру
  Використано: класи, ArrayList, millis(), стани гри
*/
```

## 6. Тестування

Попросіть однокласника пограти **без ваших підказок** і записуйте, де він заплутався або що зламалося. Перевірте «крайові випадки»:
- що буде, якщо клацати дуже швидко?
- якщо мишу вивести за межі вікна?
- якщо грати дуже довго: чи не накопичуються об'єкти, чи не гальмує?
- якщо життів 0 — чи правильно працює перезапуск?

## 7. Експорт і показ результату

| Спосіб | Як | Коли зручно |
|---|---|---|
| експорт програми | *File → Export Application* — окрема програма для Windows, macOS чи Linux | показати друзям без Processing |
| скриншоти | `saveFrame("shot-####.png")` за клавішею | портфоліо, презентація |
| відео | зберегти кадри `saveFrame("frames/####.png")` і зібрати їх у відео інструментом *Tools → Movie Maker* (є не в усіх версіях Processing) або будь-яким відеоредактором | ролик анімації |
| онлайн | переписати на p5.js (JavaScript) і поділитися посиланням з editor.p5js.org | показати в браузері |
| код | *Файл → Завантажити як .pde* в онлайн-середовищі або папка скетчу | здати вчителю |

## 8. Як підготувати презентацію (3 хвилини)

1. **Що це** (20 с): назва і одне речення-ідея.
2. **Демонстрація** (60 с): покажіть, як працює.
3. **Як зроблено** (60 с): один цікавий фрагмент коду, наприклад клас чи перевірку зіткнень, і поясніть його.
4. **Що було складно** (20 с) і як ви це розв'язали.
5. **Що далі** (20 с): що б ви додали, якби був ще тиждень.

## 9. Як користуватися довідкою Processing

Коли ви не знаєте функцію, відкрийте **processing.org/reference** або виділіть назву в редакторі → *Help → Find in Reference*. Сторінка кожної функції має однакову структуру:

| Розділ | Що там |
|---|---|
| Name | назва |
| Examples | приклади коду: найкорисніше, з них варто починати |
| Description | опис (англійською, можна скористатися перекладачем) |
| Syntax | усі варіанти виклику: `rect(a, b, c, d)`, `rect(a, b, c, d, r)` … |
| Parameters | що означає кожен аргумент і якого він типу |
| Returns | тип результату (`void` — нічого) |
| Related | схожі функції |

## 10. Критерії самооцінки

- [ ] Програма запускається без помилок.
- [ ] Є щонайменше одна власна функція з параметрами і один клас.
- [ ] Використано цикл, умову, масив або ArrayList.
- [ ] Є взаємодія або анімація.
- [ ] Назви змінних зрозумілі, код відформатовано, є коментарі.
- [ ] Хтось інший протестував програму.
- [ ] Є скриншот і короткий опис.

## 11. Перевір себе

1. Чим прототип відрізняється від готової програми? Навіщо робити спочатку прототип?
2. Що таке «чарівне число» і чому його варто замінити змінною?
3. Перелічіть три «крайові випадки», які варто перевірити в грі.
4. Як показати свою програму людині, у якої немає Processing?
