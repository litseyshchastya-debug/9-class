# Детальна теорія до уроку 5. Як працюють setup() і draw()

> Тут пояснено, як програма Processing «оживає»: у якому порядку виконуються `setup()` і `draw()`, що таке кадр, де оголошувати змінні, щоб вони «пам'ятали» значення, і як записати рух формулами.

## 1. Від статичної програми до динамічної

У перших уроках програма виконувалась **один раз** зверху вниз і зупинялась. Такий режим називають **статичним**: результат — нерухома картинка.

Щоб щось рухалося, картинку треба **перемальовувати багато разів за секунду**, щоразу трохи інакше. Так працює мультфільм: 24 малюнки за секунду, і око бачить рух.

У Processing для цього є дві особливі функції, які ви **пишете самі**, а Processing **викликає сам**.

```java
void setup() {
  // виконується ОДИН раз, на старті
}

void draw() {
  // виконується знову і знову, щокадру
}
```

## 2. Анатомія запису

```text
void      setup  ()   {   ...   }
 │          │     │   └─ тіло: команди між фігурними дужками
 │          │     └─ круглі дужки: тут могли б бути параметри (поки порожньо)
 │          └─ назва функції
 └─ тип результату: void = «нічого не повертає»
```

Фігурні дужки `{ }` позначають **блок коду**: усе між ними належить цій функції. Відступи (два пробіли) Processing не вимагає, але вони допомагають людині бачити, де починається й закінчується блок. Автоматично їх розставляє Ctrl+T.

## 3. Порядок виконання

```text
Запуск ▶
   │
   ▼
Глобальні змінні отримують початкові значення
   │
   ▼
setup()  ── один раз: size(), початкові налаштування
   │
   ▼
draw()  ── кадр 1
   │
   ▼
draw()  ── кадр 2
   │
   ▼
draw()  ── кадр 3   ... і так доки програму не зупинять ■
```

Між кадрами Processing показує на екрані те, що намалював `draw()`, і перевіряє мишу та клавіатуру.

### Що куди писати

| У `setup()` | У `draw()` |
|---|---|
| `size()` — завжди **першим рядком** | `background()` — щоб стерти попередній кадр |
| завантаження зображень і шрифтів | малювання фігур |
| налаштування, що не змінюються | зміна змінних (рух) |
| початкові значення змінних | перевірки умов (урок 7) |

## 4. Функції керування кадрами

| Функція / змінна | Аргументи | Що робить |
|---|---|---|
| `frameRate(n)` | кадрів за секунду | задає бажану швидкість (за замовчуванням **60**) |
| `frameRate` *(змінна)* | — | **реальна** кількість кадрів за секунду зараз |
| `frameCount` | — | скільки кадрів уже намальовано (1, 2, 3…) |
| `noLoop()` | — | зупиняє повторення `draw()` |
| `loop()` | — | відновлює повторення |
| `redraw()` | — | виконує `draw()` **один** раз (коли увімкнено `noLoop()`) |

```java
void setup() {
  size(300, 200);
  frameRate(10);        // повільно: 10 кадрів за секунду
}

void draw() {
  background(255);
  fill(0);
  textSize(32);
  text(frameCount, 120, 110);   // номер кадру на екрані
}
```

Змініть `frameRate(10)` на `frameRate(60)` і порівняйте швидкість лічильника.

## 5. Глобальні й локальні змінні (область видимості)

Це **найважливіша** тема уроку. Від того, **де** оголошено змінну, залежить, скільки вона «живе» і хто її «бачить».

| | Глобальна | Локальна |
|---|---|---|
| Де оголошена | **поза** всіма функціями, зазвичай угорі | **всередині** функції (між `{ }`) |
| Хто бачить | усі функції скетчу | лише та функція (блок), де оголошена |
| Скільки живе | весь час роботи програми | лише під час одного виконання функції |
| Для чого | значення, які треба **пам'ятати між кадрами**: положення, рахунок | тимчасові обчислення в межах одного кадру |

### Чому коло не рухається

```java
void setup() {
  size(400, 200);
}

void draw() {
  float x = 0;          // ❌ локальна: створюється заново КОЖЕН кадр зі значенням 0
  background(255);
  ellipse(x, 100, 40, 40);
  x = x + 2;            // збільшили до 2... але в наступному кадрі знову 0
}
```

Як виправити: перенести оголошення **нагору**, поза функції.

```java
float x = 0;            // ✅ глобальна: пам'ятає значення між кадрами

void setup() {
  size(400, 200);
}

void draw() {
  background(255);
  ellipse(x, 100, 40, 40);
  x = x + 2;
}
```

### Покрокове трасування

Простежимо значення `x` у правильній програмі:

| Кадр | x на початку `draw()` | що малюємо | x після `x = x + 2` |
|---|---|---|---|
| 1 | 0 | коло в (0, 100) | 2 |
| 2 | 2 | коло в (2, 100) | 4 |
| 3 | 4 | коло в (4, 100) | 6 |
| … | … | … | … |
| 100 | 198 | коло в (198, 100) | 200 |

За 60 кадрів (1 секунду) коло проходить 120 пікселів.

## 6. Рецепт будь-якої анімації (за Шиффманом)

1. **Оголосити** змінну вгорі: `float x;`
2. **Задати початкове значення** при оголошенні або в `setup()`: `x = 0;`
3. **Використати** в `draw()` для малювання: `ellipse(x, 100, 40, 40);`
4. **Змінити** в `draw()`: `x = x + 2;`

## 7. Формули руху

| Що хочемо | Як змінювати | Приклад |
|---|---|---|
| рух праворуч | збільшувати x | `x += speed;` |
| рух ліворуч | зменшувати x | `x -= speed;` |
| рух донизу | збільшувати y | `y += speed;` |
| рух по діагоналі | змінювати x **і** y | `x += 2; y += 1;` |
| ріст | збільшувати розмір | `d += 0.5;` |
| зміна кольору | змінювати складову | `c = (c + 1) % 256;` |
| повернення на початок | після краю — назад | `if (x > width) x = 0;` *(урок 7)* |

Чому `speed`, а не просто число? Тоді швидкість можна змінювати в одному місці, а пізніше — змінювати під час гри.

### Швидкість = пікселі за кадр

При `frameRate(60)` швидкість 2 означає 2 × 60 = **120 пікселів за секунду**. Якщо зменшити частоту кадрів, рух сповільниться, тому в серйозних програмах рух іноді рахують через час (урок 15).

## 8. Роль `background()` у `draw()`

| Де `background()` | Що бачимо |
|---|---|
| на початку `draw()` | кожен кадр з чистого аркуша, фігура «рухається» |
| лише в `setup()` | старі кадри не стираються, фігура лишає **слід** |
| напівпрозорий прямокутник замість фону | старі кадри поступово блякнуть — **шлейф** |

```java
float x = 0;

void setup() {
  size(400, 200);
  background(0);
}

void draw() {
  noStroke();
  fill(0, 20);                 // чорний, майже прозорий
  rect(0, 0, width, height);   // «туман» поверх старих кадрів
  fill(255, 200, 0);
  ellipse(x, 100 + sin(frameCount * 0.1) * 50, 20, 20);
  x = (x + 3) % width;         // після правого краю — знову з 0
}
```

*(`sin()` дає хвилясту траєкторію; докладно — урок 13.)*

## 9. Типові помилки

| Що сталося | Причина |
|---|---|
| нічого не рухається | змінну оголошено всередині `draw()` |
| фігура лишає «смугу» | немає `background()` на початку `draw()` |
| `size()` не спрацював | він не перший рядок `setup()` або стоїть у `draw()` |
| `Duplicate method draw()` | у скетчі дві функції `draw()` |
| програма малює лише один раз | у скетчі немає `draw()` (статичний режим) або викликано `noLoop()` |

## 10. Шпаргалка

```java
float x = 0;              // глобальна — пам'ятає між кадрами

void setup() {            // 1 раз
  size(400, 400);
}

void draw() {             // ≈60 разів за секунду
  background(255);        // стерти
  ellipse(x, 200, 40, 40);// намалювати
  x += 2;                 // змінити
}
```

## 11. Перевір себе

1. Скільки разів виконається `setup()`, якщо програма працює 10 секунд? А `draw()`?
2. У яких двох місцях можна задати початкове значення глобальної змінної?
3. Коло рухається зі швидкістю 3 пікселі за кадр при 30 кадрах за секунду. Скільки пікселів воно пройде за 2 секунди?
4. Що робить рядок `x = (x + 3) % width;`?
5. Як зробити, щоб анімація зупинилась після 300 кадрів?

<details>
<summary>Відповіді</summary>

1. `setup()` — 1 раз; `draw()` — приблизно 600 разів (60 кадрів × 10 секунд).
2. При оголошенні (`float x = 0;`) або в `setup()` (`x = 0;`).
3. 3 × 30 × 2 = 180 пікселів.
4. Збільшує x на 3, а коли x доходить до ширини вікна, остача повертає його до початку.
5. Наприкінці `draw()`: `if (frameCount >= 300) noLoop();`

</details>
